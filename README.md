# A股估值模型填充 · Web 版

办公人员上传财报 PDF，系统产出填好数据的 `.xlsm` 估值模型。结论卡及报告展示暂时隐藏。
**服务端不需要 Excel、不需要 Windows、不需要 pywin32**，Linux 和 Docker 都能跑。

## 怎么跑

Windows（双击也行）：

    python -m pip install -r requirements.txt
    python app.py

Linux：

    sh 启动.sh

Docker：

    docker compose up -d --build

然后打开 `http://127.0.0.1:8000`。Linux / 容器里想让同网段的人访问，
用 `HOST=0.0.0.0 PORT=8000 python app.py`（Docker 镜像里已经是这个设置）。

## 它是怎么摆脱 Excel 的

模板里有 876 个格子参与**循环引用**（`workbook.xml` 的 `calcPr iterate="1"`
就是为它们开的）。实测：Excel 从它自己文件里存的迭代起点出发才收敛到它的解，
Python 冷启动算出来是另一个数（`绝对估值!D40`：Excel 3067.60，冷启动 -936.63）。
所以服务端**不复现**这部分计算，而是把它交回给 Excel：

    服务端（Linux，无 Excel）
      PDF 解析 -> 字段映射 -> 写模板输入格 -> 产出 .xlsm（公式一个不少）
                                                缓存值留空 + fullCalcOnLoad="1"
                                                       |
    办公人员在自己电脑用 Excel 打开 --------------------+
      Excel 自动重算，得到与直接用 Excel 跑这份模板一致的结果

证据：把本 Web 版产出的模型交给真实 Excel 重算，与原先 COM 路径产出的模型
逐格比对，26 个关键格（`绝对估值!D40/D38/D39/D41`、`相对估值!D82`、
`营运资本!I38/I62`、`输出!B58/B60/B62`、`报告期历史数据` 各列、`利润表` …）
**全部一致**；其中 4 格显示「不同」只是错误值的两种写法（`#DIV/0!` 字符串
和它的整数码 `-2146826281`），是同一个值。

### 这个差别对使用者意味着什么

- 产出的 `.xlsm` **必须用 Excel 打开**才有数字。用不支持重算的工具（某些
  在线预览、纯读取脚本）看到的会是一片空白，那不是文件坏了。
- 网页只展示运行状态和下载入口，不展示结论卡、年份明细或完整报告。
  后台报告生成逻辑和历史文件保留，报告接口暂时关闭，便于后续完善。
- 如果哪天真要在服务端出准确的估值数字，只有三条路：① 改造模板消除循环引用
  （根治，但要重做利润表/现金流量/资产负债的相关公式并需财务复核）；
  ② 保留一台 Windows + Excel 的计算节点；③ 接受 30.6% 的格子不精确。

## 目录

    web部署版本/
      app.py            网页入口（Flask）
      config.py         路径与常量
      store.py          SQLite 任务库
      worker.py         串行后台 worker
      runner.py         调流水线、解析进度
      prefill.py        上传后先认料，把参数表单预填好
      templates/        页面
      static/           前端资源
      engine/           纯 Python 读写 xlsm（直接改 zip 内的 XML）
      pipeline/         财报解析 → 字段映射 → 写模型 → 判定 的流水线
        config/         字段字典、验收断言、清理清单
        scripts/        各步骤脚本；com_excel.py 是写工作簿的后端
     原件/             随项目发布的模板 .xlsm（按 sha256 认，不按文件名）
      data/             运行时生成：任务库、上传的 PDF、产出的模型

## 上游依赖面

主要依赖：`Flask`、`pdfplumber`、`openpyxl`、`olefile`、`waitress`、`psutil`。
原先的 `pywin32` 依赖已经去掉 —— 整个项目里唯一碰 COM 的地方是
`pipeline/scripts/com_excel.py`，那个文件已经被换成纯 Python 实现。

## 想改字段映射 / 断言

- 某个科目在 PDF 里换了写法 → 往 `pipeline/config/mapping.json` 对应行的
  `match` 列表里加词。
- 季报/半年报的科目 → `pipeline/config/mapping_quarterly.json`。
- 写入后的检查项 → `pipeline/config/assertions.json`。注意：**落在公式格上的
  「值非零 / 不等于某数」这类断言在服务端不可判定**，流水线会把它们标成
  「待 Excel 重算」而不是失败 —— 这不是放水，是因为服务端确实没有那个数。

## 一两人内部使用

Windows 日常操作：双击 `启动.bat`，保留弹出的服务窗口，然后用浏览器打开
`http://127.0.0.1:8000/`（建议加入收藏夹）。不用时回到服务窗口按 `Ctrl+C`；
若出现终止批处理询问，输入 `Y`。关闭网页不会停止服务。不需要反复双击启动。
启动失败时窗口会保留报错，截图即可排查。BAT 内容刻意使用 ASCII，避免中文编码导致命令解析错误。

- 启动方式仍是 `python app.py` 或双击 `启动.bat`，服务由 Waitress 承载；只运行一个实例。
- 更新后先执行 `python -m pip install -r requirements.txt`，再重启服务。数据库会自动补充运行记录表，不删除历史数据。
- 本机默认仅监听 `127.0.0.1`。局域网共享时设置 `HOST=0.0.0.0`，并用防火墙只放行指定办公电脑；没有账号隔离，不应暴露到公网。
- Docker 默认仅本机可访问；局域网使用时设置 `BIND_IP=0.0.0.0` 并配置同样的防火墙限制。
- 一个任务只会入队一次。服务中断后遗留任务标为失败，不自动重跑；确认文件后点击“重新生成”。未完成识别的上传需要重新上传。
- 本次运行目录有 `.xlsm` 文件就允许下载，不以写入记录、指纹或验收通过为门槛；异常只提示。若只有中间模板，按钮显示“下载中间文件”，任务不算成功。文件必须属于本次运行目录，不能下载目录外的文件。
- “待复核”表示模板已填充，但需要在 Excel 中重算或人工复核，不代表已验证最终估值。系统不替用户编造预测假设，也不要求上传六份年报。

### 日志与排查

办公人员只需提供失败页的任务编号，无需理解日志。

| 位置 | 内容 |
| --- | --- |
| `data/logs/app.jsonl` | 应用事件、异常堆栈、任务/运行编号、阶段耗时和退出码 |
| `data/tasks/<任务编号>/_detect.log`、`_prefill.log` | 上传识别与预填过程 |
| 任务的 `估值结果/<运行目录>/_web_run.log` | 带时间戳的流水线完整输出 |
| 同目录的 `audit.json`、`params.json` | 本次生成状态、参数及模板/产物指纹 |
| 同目录的 `_AI参考_可删/` | 字段来源、写入回读和验收证据；排查期间不要删除 |
| `data/webapp.db` 的 `task_runs` | 每次生成的独立编号、状态、时间、耗时及退出码 |

应用日志每份最多 5 MB，最多保留 5 份历史轮转文件；任务证据不自动删除。
默认识别超时 120 秒、预填 900 秒、生成 1800 秒，可分别通过
`DETECT_TIMEOUT_SECONDS`、`PREFILL_TIMEOUT_SECONDS`、`PIPELINE_TIMEOUT_SECONDS` 调整。
超时会终止该次子进程树，不继续阻塞后续任务。健康检查为 `GET /healthz`。

### 备份与保留

小规模内部使用建议每周停服后备份整个 `data/`，同时保留当前代码、`requirements.txt` 和原件模板。
恢复时停服还原上述内容，再启动；同机原路径恢复最简单，换路径迁移需同步更新数据库及运行记录中的绝对路径。
默认不自动删除任务，避免误删报告。空间不足会阻止新上传/生成；定期检查磁盘，将长期不用的数据离线归档。
备份和日志仅维护人员访问，不要把包含上传文件与路径的诊断资料公开分享。

### 回归验证

项目根目录执行 `python _verify/test_internal_web.py` 和 `node _verify/test_internal_web_ui.js`。
验证使用临时数据库和模拟产物，不改真实任务；实际 PDF 生成和 Excel 数值复核仍应作为业务验收。
